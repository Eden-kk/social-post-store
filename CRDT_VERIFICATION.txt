Independent CRDT counter extension — 2026-10-12

Scope
Raft SQL remains majority committed. A separate PN-counter namespace permits
origin-local signed increments/decrements during logical partitions. It does not
merge arbitrary SQL writes, offer cross-mode transactions or enforce nonnegative
balances. The process remains loopback only and untrusted callers are unsupported.

API
GET /counter/status -> origin=<node-id>:<incarnation-UUID>, pending peer count,
lastFailure (historical last replication failure, not a current-health assertion).
POST /counter/add with X-Counter-Origin=<exact origin> and X-Request-ID=<stable ID>
and body consisting of key, newline, signed long delta. Response LOCAL_DURABLE
means one local forced/atomically replaced copy, never remote durability/quorum.
Retry same ID, payload and origin. Do not route one logical increment to another
origin; wrong-origin retries reject. Duplicate retries return the original local
result, not necessarily today's aggregate. POST /counter/read with key as body
returns an eventual, potentially stale local value. There is no reset/delete/set.

Mechanism
Each key retains nonnegative P/N components per incarnation. Receiver merges
componentwise max, never adds delta messages. Aggregate arithmetic is BigInteger;
individual long component overflow rejects before state mutation. The same
atomic file includes state, local request/result dedup and per-peer acknowledged
version. Snapshot versions newer than an ACK remain pending. Full-state messages
coalesce pending work; this is a durable local outbox, NOT an external MQ broker.
Receiver acknowledges only after durable merge. Immediate sends have bounded
timeouts, and background full-state anti-entropy runs even when pending is zero.
Incoming advancement of the current local incarnation fails closed as stale or
cloned identity; missing identity/state pairing is rejected. Entirely new data
directory generates a fresh incarnation; never copy a live identity to a writer.

Bounds and limitations
Fixed three peers; no dynamic membership, auth/TLS, Kafka, physical cross-region
deployment or production fault-tolerance claim. Individual wire snapshots capped
at 900,000 bytes; global union must remain within that bound. If a merge exceeds
it, the receiver fails closed without ACK; capacity exhaustion is NOT covered by
convergence guarantees. Max 100,000 retained local request IDs; no garbage
collection. Whole-state fsync/replace per mutation is deliberately non-scalable.
Full site/disk loss before remote delivery may lose acknowledged local writes.
Restore of an old snapshot under a reused incarnation is unsafe and unsupported.
Eventual convergence assumes bounded state, updates stop and delivery resumes.
